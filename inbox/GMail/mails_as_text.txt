Subject: Vessel Library System / Vessel Database – Initial Requirements for Review

Hi Stian,
We shortly discussed about how we can better capture and retain vessel-related information, documentation, project history, and company experience in one place.
The objective is to create a simple first version of a Vessel Library System that allows users to quickly search for a vessel by name, IMO number, or project number and immediately access all available information associated with that vessel or vessels.
The intention is to start simple and practical, not to build a complex engineering tool from day one. However, the architecture should allow future expansion if we decide to add more advanced functionality later.
For reference, some existing vessel databases and vessel profile sites that demonstrate the general concept are:

 *   IMO GISIS<https://gisis.imo.org/Public/Default.aspx>
 *   VesselFinder<https://www.vesselfinder.com/vessels>
 *   Vessels Info<https://vesselsinfo.com/>
 *   Sea Project Vessel Lookup<https://www.seaproject.live/lookup>

I am not suggesting we replicate these systems, but they provide good examples of vessel profiles, searchable vessel characteristics, and document organization.
The points below are intended as initial suggestions just as a base to discuss rather than fixed requirements. We can review and refine them together, then maybe discuss them with Esten and Rolf-Atle and maybe Carl also to gather their input as well.

Vessel Records
Each vessel shall have a master record containing:

 *   Vessel Name
 *   IMO Number (if available)
 *   Vessel Type
 *   Previous Names (optional)
 *   Other identifiers (optional)

The system should support configurable vessel properties such as:

 *   LOA
 *   LWL
 *   LBP
 *   Beam
 *   Draft
 *   Displacement
 *   GT
 *   DWT
 *   Builder
 *   Year Built
 *   Flag
 *   Class Society
 *   Owner

    New vessel properties should be easy to add in the future without requiring major software modifications.
Document Management
Ability to upload and store vessel-related documents, for example:

 *   General Arrangements
 *   Docking Plans
 *   Stability Booklets
 *   Lines Plans
 *   Technical Reports
 *   Drawings
 *   PDFs
 *   CAD Files
 *   Customer Documentation
 *   Internal Documentation

Each document should include:

 *   Title
 *   Category
 *   Revision (if applicable)
 *   Upload Date
 *   Uploaded By

Image Management
Ability to upload and store:

 *   Vessel photographs
 *
Site photographs
 *
Load reading
 *   Inspection photographs
 *   Screenshots
 *   Technical illustrations

Project History
A vessel may be linked to multiple projects.
For each linked project:

 *   Project Number
 *   Project Name
 *   Customer
 *   Location
 *   General description

    This should make it easy to identify where and when we have previously been involved with a specific vessel.
Notes and Experience
Users should be able to add notes related to:

 *   Previous experience
 *   Lessons learned
 *   Recommendations
 *   Known issues
 *   Customer-specific observations
 *   General remarks

Search Functionality
Search by:

 *   Vessel Name
 *   Previous Vessel Name
 *   IMO Number
 *   Project Number
 *   Project Name
 *   Document Title
 *   Keywords within notes

Traceability
All changes should be logged automatically:

 *   User
 *   Date
 *   Time
 *   Action performed

Records should be archived rather than permanently deleted.
User Roles
Viewer

 *   Search and view information

Contributor

 *   Create vessel records
 *   Upload documents
 *   Upload images
 *   Add notes
 *   Link projects

Administrator

 *   Manage users
 *   Manage permissions
 *   Maintain categories
 *   Restore archived records

Future Possibilities (Not Part of Phase 1)
The initial implementation should focus only on information management and knowledge retention.
Potential future developments could include:

 *   Automatic extraction of information from uploaded PDFs
 *   AI-assisted search
 *   Integration with external vessel databases
 *   Integration with project-management systems
 *   APIs for external applications
 *   Advanced analytics and reporting

These are not part of the initial scope but should not be excluded by the chosen architecture.
Please review and let me know whether you think something important is missing or unnecessarily complicated before we discuss it further with development.
